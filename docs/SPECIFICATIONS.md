## 1. 翻訳モデルと実行環境

### モデルの選び方

アプリの「モデル」画面では、PFN 公式の PLaMo 0.8B / 2B / 8B / 31B から大きさを一つ選びます。各行は Q4_K_M の GGUF です（機器情報はPC内でのみ処理します）。

- **一覧**：大きさごとに一行で、行のどこを押しても選べます。右端に「使用中」「保存済み」「おすすめ」のどれかが出ます。ほかの量子化（Q2_K・Q3_K_M・Q4_0）を使っているときは、その大きさの行に「使用中（Q3_K_M）」と出て、行を選び直すまでそのまま選ばれています。
- **おすすめ**：GPUの空きが 16 GiB 以上なら 8B、それ未満なら 2B、GPUがなければ 0.8B です。使用中のモデルがあれば、それが最初から選ばれます。
- **選べない行**：薄く表示し、理由を右端に出します（「GPUが必要です」「GPUメモリが足りません（あと◯◯ GB）」など）。保存済みのモデルと使用中のモデルには、保存先の空き容量の条件をかけません（取得し直さないためです）。
- **GPUメモリの欄**：専用VRAM全体に対して、使用中の量（灰色）と、選んだモデルの見積もり（緑。入らないときは黄色）を重ねて示します。この画面を開いている間だけ、約3秒ごとに測り直します。NVIDIA は nvidia-smi で測ります。それ以外のGPUはWindowsが示す利用可能量からの目安で、「目安」と表示します。読み込み済みのモデルを選んだときは何も足さず、別の大きさを選ぶと、読み込み済みの分は入れ替わるものとして数えます。
- **CPUだけのPC**：GPUが見つからないPCと、「GPUを使わずCPUで実行する」をオンにしたPCでは、0.8B だけを選べます。llama.cpp は NPU を使わないので、CPUかNPUだけのPCは同じ扱いです。この規則は `jimoto-setup` にも同じように働きます。

### 初回準備（「はじめる」）

モデル画面の「はじめる」は、リアルタイム翻訳に要るものを、次の順に一つずつ準備します。画面には「2/3 英語の文章区切り補助を準備中」のように段階を出し、その下に取得の進み具合を出します。

1. **翻訳モデル**：選んだモデルと llama.cpp の実行環境です。取得先と検証はこれまでと同じです。選んだモデルがすでに使用中で、同じ実行環境で読み込まれているときは、取得も再読み込みもしません。
2. **英語の文章区切り補助**：チェックを外すと省きます。
3. **音声認識**：音声認識が Nemotron Speech で、翻訳元の言語が英語か自動判定のときに準備します。Nemotron は英語だけを聞き取るので、ほかの言語のときは準備しません。GPUがVulkanに対応していればVulkan、なければCPUです。QwenやWhisperを選んでいる環境は変えません。それらは設定から準備します。
4. **読み上げの声**：設定の「その他の機能」にある「読み上げを使う」がオンのときだけ準備します。

- **ダウンロードするもの**：モデルの一覧の下に、「はじめる」で取得するもの（上の1〜4のうち、準備するもの）を、1行ずつ大きさと並べます。保存済みのものは「保存済み」と出します。その下に、保存先（ZIPを展開したフォルダの `data`）と「フォルダーを開く」、モデルの利用条件のリンクを置きます。
- **ボタンの合計**：まだ取得が必要な量の合計です。保存済みの分は数えず、途中まで取得した分は残りだけを数えます。すべて保存済みなら「はじめる」だけになります。
- **終わったとき**：「準備ができました。」と出ます。モデルの画面を開いたままなら、チャットが開きます。準備のあいだにほかの画面へ移っていたときは、その画面のままです。音声の取得は始まりません。
- **失敗したとき**：できた段階は、そのまま使えます。止まった段階を「3/3 音声認識を準備できませんでした」のように一行で示し、詳しいエラーは「エラーの詳細」に出ます。「もう一度」で、止まった段階から続けます。
- **データのフォルダーを移したとき**：別の場所へ移したりコピーしたりしたあとも、ファイルが固定された内容と一致していれば、取得し直さずに検証して、記録だけを書き直して続けます。
- **中止**：いま進んでいる段階だけを止めます。前の段階は残り、止めた段階のファイルは、検証が終わるまで使いません。取得の途中のデータは、次回に続きから取得します。
- 選ぶモデルやチェックを変えると、止まった状態は消えて、最初の「はじめる」に戻ります。

### 共通の条件

- モデル候補は計14種類の GGUF です（0.8B / 2B / 8B / 31B。Q2_K・Q3_K_M・Q4_0 を含む）。画面に出るのは各サイズの Q4_K_M の4つです。ほかの量子化は `jimoto-setup --install --model <id>`（例：`plamo3-8b-q3_k_m`）で入れられます。
- 取得先コミット・ファイルサイズ・SHA-256 を固定して検証します。中断時は未完了ファイルから再開できます。
- 既存の導入済みモデルを自動で別モデルへ置き換えることはありません。

### `jimoto-setup` の方針

画面は常に「リアルタイム優先」で決めます。`jimoto-setup --policy` では次の三つを選べます。

| 方針 | GPU利用時の目安 | CPU利用時 |
| --- | --- | --- |
| リアルタイム優先（`realtime`、既定） | 空きが 16 GiB 以上なら最大 8B、それ未満なら最大 2B | 0.8B |
| バランス優先（`balanced`） | 最大 8B | 0.8B |
| 品質優先（`quality`） | Q2_Kを除き、空き容量に収まる最大の大きさ（同じ大きさならQ4_K_M→Q3_K_M→Q4_0） | 0.8B |

### 翻訳ランタイム（llama.cpp b12119）

- **対応バックエンド**：CPU / Vulkan / CUDA 12.4
- **NVIDIA CUDA 条件**：Windows ドライバー 551.61 以上（共有GPUメモリーは専用VRAMに含めません）
- **必須ランタイム**：翻訳用 `llama.cpp` と英語区切り補助には [Microsoft Visual C++ v14 再頒布可能パッケージ（x64）](https://learn.microsoft.com/ja-jp/cpp/windows/latest-supported-vc-redist?view=msvc-170) が必要です（アプリ本体・セットアップCLIは静的リンク済み）。

## 2. 画面・画像の文字認識（OCR）

設定の「その他の機能」にある「画面・画像の文字認識」から方式を切り替えられます。画像はすべてPC内で処理します。

| 方式 | 初回取得量 | 特徴・動作条件 |
| --- | --- | --- |
| **Windows OCR**（初期設定） | 追加なし | Windows標準の文字認識を使用。 |
| **Indra OCR** | 約184MB（日英9モデル約54MB＋専用Python・23パッケージ） | 軽量なCPU向け。行ごとに言語を自動判定。システムPythonやPATHは変更しません。 |
| **PaddleOCR-VL-1.6** | 約1.82GB（展開込み空き目安 約4GB） | 精度重視。翻訳用 `llama.cpp` を再利用するためPython不要。CPU固定またはGPU自動判定を選択可能。 |

「画面の文字を翻訳」は、選んだ範囲を一定の間隔で読み取り、文字が変わったときだけ翻訳します。間隔は、この設定で1秒・1.5秒・2秒・3秒から選びます（初期値は1.5秒）。画像はメモリ上だけで扱い、ファイルには保存しません。

## 3. ライブ字幕（段落結合・英語区切り補助）

- **段落単位の翻訳更新**：YouTube字幕や音声認識の短い断片を1行ずつ区切らず、話のまとまりごとに段落へつないで翻訳を更新します。直前の確定段落も文脈として参照します。話している途中の段落は、8語増えるごとに訳し直します。語の追加が1.2秒止まったときは、8語未満の残りも訳し直します。どちらも、前に頼んでから2秒たつまでは待ちます。設定の「文章をつなぐ翻訳」の「区切りの長さ」で、段落の長さを短め（1〜2文ほど）・標準（2〜4文ほど。初期値）・長め（段落ごと）から選べます。訳し終えて確定した段落は、あとから変わりません。
- **やさしい日本語での表示**：翻訳先が日本語のとき、段落を1回訳すたびに、PLaMoに2回頼みます（話している途中の段落を訳し直すときも、そのたびに2回です）。1回のときより、訳文が出るまでに時間がかかります。
  - 1回目は、設定の文体・文脈・用語集を使って、原文を日本語に訳します。
  - 2回目は、1回目の日本語を、原文言語 `ja`・翻訳先 `ja(easy)` で書き直します。`ja(easy)` は PLaMo 3 Translate 公式テンプレートの「やさしい日本語」です。2回目には、文体・文脈・用語集を渡しません。
  - 画面、履歴、字幕ウィンドウ、書き出し、自動読み上げに使うのは、2回目の訳文です。次の段落の文脈として渡す直前の訳文は、1回目の日本語のままです。
  - 2回目が失敗した段落は、1回目の訳文を表示します。段落の失敗にはしません。
  - 翻訳先が日本語以外のときは、これまでどおり1回です。ファイル翻訳とシンプル翻訳の画面は変わりません。
- **履歴の項目**：履歴（JSONL）の `translation` は、表示した訳文です。2回目が成功した段落だけ、1回目の訳文を `standard_translation` に残します。この項目がない履歴も、そのまま読み込めます。JSON の書き出しには `standard_translation` も入ります。TXT と SRT には表示した訳文を書き出します。
- **チャット表示**：訳文は、古いものを上、新しいものを下にしたチャットで読みます。背景は青みがかった灰色、訳文は白い吹き出しで、文字の大きさは「その他」→「表示」の文字サイズに従います。チャットと字幕ウィンドウは同じ部品で描きます。「その他」→「表示」（ミニ表示では「⋯」→「表示」）の「ダークモード」をオンにすると、チャットの背景をほぼ黒に、吹き出しを濃い灰色に、文字を明るい色にします。画面のアイコンは、暗い背景で見分けられるよう少し明るい紫にします。ミニ表示と字幕ウィンドウのチャットも同じ色になり、切り替えはすぐに反映されます。チャットのまわりの画面は、もともと暗い色のままです。初期値はオフで、ほかの設定と同じく設定ファイルに保存します（「設定を保存」と終了のとき）。この項目のない前の版の設定ファイルでは、オフです。
  - **送り手**：入力元（YouTube・PC音声・画面）ごとに、色の違う丸いアイコンと名前が付きます。同じ入力のメッセージが2分未満の間隔で続くあいだは、アイコンと名前を1つにまとめます。
  - **時刻と日付**：吹き出しの右下に、記録の `created_at` の時刻（例：21:48）を出します。日が変わるところには日付（例：11月7日（土））を出します。
  - **更新中と未確定**：更新中の文章は薄い文字のあとに動く3つの点を付けます。訳文がまだないあいだは、聞き取った英語をそのまま小さな薄い文字で表示して点を付け、訳文が届くと日本語に置き換わります。英語もまだないときは、点だけの吹き出しにします。失敗・中断した文章は、最後の訳文の下に小さな注記を付けます。動画の終わり・シーク・別の動画・入力の切り替え・終了で止まった文章でも、訳文が文章の全体に追いついていれば、確定した文章として注記なしで表示します。「自動」で字幕に戻ったときや、字幕が消えてPC音声に戻ったときのように、音声認識が動き直したときも、PC音声で聞き終えた文章は最後まで訳して確定します。
  - **話者の交代**：YouTube字幕の `>>` は表示せず、話者ごとに別の吹き出しにします。
  - **長い段落**：訳し終えた話者の文章は、文の切れ目で約60字ごとの吹き出しに分け（更新中の文章は分けません）、時刻・原文・コピー・新しいメッセージの数は、分けても1つの吹き出しと同じに扱います。かぎかっこ（二重かぎかっこを含む）と丸かっこの中にある文の切れ目では分けません。閉じていないかっこがある文章は、かっこがないものとして文の切れ目で分けます。
  - **原文**：吹き出しをクリックすると、英語の原文を訳文の下に出します（YouTubeでは「動画 00:12:34」も）。もう一度押すと閉じます。「その他」→「表示」の「原文をすべて表示」で、すべてを開きます。
  - **コピーと読み上げ**：吹き出しを右クリックすると「コピー」ができます（クレジット付き）。「読み上げを使う」がオンのときは「読み上げ」も選べます。吹き出しの文字はドラッグで選べ、`Ctrl+C` か右クリックの「選択範囲をコピー」で、選んだ部分だけをコピーします（これもクレジット付き）。
  - **追従**：末尾にいるあいだは、最新のメッセージに追従します。上へスクロールすると追従をやめ、届いたメッセージの数を「↓ 新しいメッセージ 3件」で知らせます。押すと末尾へ戻り、追従を再開します。「その他」→「表示」で「末尾へ自動スクロール」をオフにすると、末尾にいても追従しません。
- **英語の文章区切り補助（任意）**：
  - 初回取得は約86MB（空き容量目安 512MiB以上）。`sherpa-onnx 2.0.1` と `CT-Transformer INT8` をCPUで実行します。
  - 補助を使うのは、話している途中の段落が長さか時間の上限に達して、文の切れ目で分けるときだけです。
  - 補助モデルの出力が元の単語や数字を変えた場合は破棄します。翻訳に渡す文は、補助モデルの出力ではなく常に元の原文です（言いよどみの除去は次の項目）。
- **言いよどみの除去**：英語の字幕・音声では、単独の `um`・`uh`・`er`・`erm`・`hmm`・`mm`（先頭だけ大文字のものと、直後のカンマを含む）を、翻訳に渡す原文と、文脈として参照する直前の確定段落の原文から取り除きます。`um.` のように他の記号が付いた語、`uh-huh`・`umbrella`・`ER` のような別の語や略語、`5 mm` の単位は残します。言いよどみだけの文は、訳す文字がなくならないようそのまま渡します。画面の文字と英語以外の原文は変えません（`um` や `er` が普通の語である言語があるため）。段落の原文と履歴には言いよどみが残ります。
- **金利の分数**：英語の字幕・音声・画面の文字では、1/4・1/2・3/4 の分数を、翻訳に渡す原文と、文脈として参照する直前の確定段落の原文で小数に直します。YouTubeの自動字幕の `3 and 3/4` と、FOMCの声明の `3-3/4` は `3.75` になります。整数のない分数は、すぐ後ろに `%` か ` percent`（` percentage point` を含む）があるときだけ直します（`1/4 percentage point` は `0.25 percentage point`、`0 to 1/4 percent` は `0 to 0.25 percent`）。整数は1〜99だけを対象にし、`0 and 1/4`（0から1/4までの範囲のことがあります）や `2025 and 1/2` のような年は、そのまま渡します。日付の `3/4`・`11/4`・`1/2/2026`、`3/4ths`、ほかの分数（`1/3` など）、英語以外の原文も変えません。`5 1/4 percent` のように、整数と分数を空白でつないだ書き方も、そのまま渡します（分数だけを直すと `5 0.25 percent` になり、数が2つに見えるためです）。画面の文字は、言いよどみは除かず、分数だけを直します。言いよどみを除いたあとに直すので、`3 and uh 3/4` も `3.75` になります。段落の原文と履歴には分数が残ります。
- **金融（FOMC記者会見）の用語**：設定の「用語集と文脈」の「金融（FOMC記者会見）の用語を入れる」は、FRBの記者会見向けの30語を、用語集の欄の最後に「原語 = 訳語」の行で足します。原語が同じ行がすでにあれば（大文字と小文字の違いは同じとみなします）、その語は足さず、今の訳語を残します。欄が100項目に達したら残りは足さず、足さなかった数を状態の行に出します。文脈の欄は変えません。足した行は、「設定を保存」のあと1回目の翻訳に使われます。足したあとの状態の行とボタンのホバーで、ほかの話題を訳すときは消すよう伝えます（たとえば Governor は、州知事のことも「理事」と訳します）。用語集は100項目までです。1行の原語と訳語は、それぞれ256文字までで、「<|plamo:」を含められません。合わない行があると、欄の下にその行の番号と理由を出し、「設定を保存」を押せなくします。
- **書き出し**：いまの会話だけを書き出します（「クリア」で消した会話は入りません）。動画変更や終了時に途中だった文章は「未確定」として保持します。TXT / JSON には未確定分も含め、SRT には確定済みの訳文のみを書き出します。SRTに書き出せるのは、PC音声だけ、または1本のYouTube動画だけの履歴です（ほかの履歴では、そう出して、TXTかJSONを選ぶよう案内します）。

## 4. PC再生音声の認識（STT）

Windowsの既定出力で再生中の音声を取得します（マイク入力ではありません）。Nemotron は初回の「はじめる」で準備します（翻訳元の言語が英語か自動判定のとき）。Qwen・Whisper は、設定で選んでから「音声認識を準備」で導入します。すでに Qwen か Whisper を選んでいる環境は、モデルを準備し直しても変わりません。

| モデル | 対象言語・実行方式 | 初回空き容量の目安 | 特徴 |
| --- | --- | --- | --- |
| **Nemotron Speech Streaming 0.6B** | 英語専用（CPU / Vulkan） | 約2GB | 約700MBの公式Q8_0 GGUF＋`NeMo-Speech.cpp 0.3.0`。Python不要。160msまたは560ms単位で連続認識。 |
| **Qwen3-ASR-0.6B-hf** | 多言語（CUDA / CPU） | CUDA: 14GiB / CPU: 8GiB | 2〜4秒区間ごとに認識。CUDA 12.8版はNVIDIAドライバー 570.65 以上を別途確認します。 |
| **Whisper base** | 多言語（CPU） | 4GiB | 対応GPUを確認できない環境向けの多言語モデル。 |

- **Nemotronが聞き取れない言語**：Nemotron は英語だけを聞き取ります。音声認識が Nemotron で、翻訳元の言語（設定の「翻訳する言語」）が英語でも自動判定でもないとき、「聞く」はPC音声を始めず、Nemotronの準備の確認も読み込みもしません（「自動（字幕を優先）」では字幕だけを始めます）。「はじめる」も Nemotron を準備しません。このあいだ、注意の色で「Nemotronは英語だけを聞き取ります。中国語などほかの言語は、設定の「音声認識」でQwen3-ASR（GPU・数GB）かWhisper（CPU・約4GB）を選んでください。」と出します。「聞く」の横の一行には、入力がPC音声を使うとき（「PC音声だけ」と「自動（字幕を優先）」）に出し、「YouTube字幕だけ」と「画面の文字」では出しません。設定の「音声認識」には入力によらず出し、その下の「音声認識を準備」を押せなくします。英語か自動判定に戻すか、ほかの音声認識を選ぶと、文は消え、「音声認識を準備」も押せるようになります。聞いている途中で翻訳元の言語を変えたときは、PC音声を止めて、同じことを出します。設定の選択肢は「Qwen3-ASR · 多言語 / GPU · 数GB」「Whisper · 多言語 / CPU · 約4GB」と、多言語であることと大きさを書きます。
- Qwen・Whisper 用の `uv`・管理Python 3.13・仮想環境はアプリ専用領域に作成し、システムのPython環境には影響しません。
- **音の途切れの判定**：Nemotron は、Windowsが音のかたまりごとに付ける時刻が20 msより大きく飛んだときだけ、認識をやり直します。Windowsの途切れの印（`AUDCLNT_BUFFERFLAGS_DATA_DISCONTINUITY`）は使いません。途切れのない音でも、すべてのかたまりにこの印が付くPCがあるためです。Qwen・Whisper の2〜4秒の区間も、この印では捨てません。

## 5. 日本語の読み上げ（TTS）

設定の「その他の機能」にある「訳文の読み上げ」で「読み上げを使う」をオンにすると、**Irodori-TTS v4.1 Small-MF** と **speech.cpp 0.10.1** を追加できます。既定はオフです。オフの間は、読み上げのボタン・自動読み上げ・「状態の詳細」の「読み上げ」を表示せず、訳文を自動で読み上げることもありません。オフにすると、読み上げ中の文も止まります。

- **必要容量**：初回取得 約1.95GB（展開込み空き容量の目安 約4.4GB）。Python不要。
- **動作条件**：Windows版の `speech.cpp` はCPU実行時でもシステムの Vulkan ローダーが必要です。起動時に空きVRAMが 4GiB 未満の場合は自動でCPU実行に切り替えます。
- **固定声**：初回再生時または設定から「標準の固定声」を作成します。手元のWAV（1〜120秒・64MiB以内）から声の特徴をGGUFとして登録することも可能です。
- **速度調整とループ防止**：基準速度は 0.8〜1.6倍。ライブ翻訳の自動読み上げ時は、遅延に応じて自動加速します。上限は既定で 1.8倍で、「自動調整の上限」で 1.2〜2.0倍から選べます（基準速度より下にはなりません）。「ライブ字幕の遅れに合わせて速度を上げる」をオフにすると、加速しません。読み上げ再生中はアプリ自身の声をPC音声認識へ取り込まないよう抑止します。

## 6. 画面の構成・ミニ表示・字幕ウィンドウ

- **ホーム画面はチャット**：起動するとチャットを開きます。翻訳モデルが入っていないときだけ、先にモデルの画面を開きます。チャットの上には「Talk風Live翻訳」、「シンプル翻訳」、「全文コピー」、「クリア」、「⋯ その他」を置き、チャットの下に「聞く」のバーを置きます。「シンプル翻訳」はいつでも押せ、シンプル翻訳の画面を開きます（ホバーは「左に入れた文を、右に訳します。」）。「クリア」は表示中の会話を消して、新しく始めます。消した会話は、履歴の画面の「これまでの会話」に残ります。「全文コピー」と「クリア」は、チャットに出ているもの（YouTube・PC音声・画面）だけを扱います。「全文コピー」はチャットに訳文がないとき、「クリア」はチャットに何も出ていないときは押せません。シンプル翻訳の画面でまだ訳している途中の翻訳は、「クリア」を押しても消えません。新しい会話を始められないときは、「新しい会話を始められませんでした（…）」と出して、いまの会話を残します。
- **空のチャット**：メッセージがないあいだ、チャットのまん中に、次にすることを出します。止まっているときは、チャットの説明「PCで再生中の英語の音声を、ここにやさしい日本語で表示します。」と「下の「● 聞く」を押すと始まります。」です。「YouTube字幕も訳す」がオンのときは、説明を「PCで再生中の英語の音声やYouTube字幕を、ここにやさしい日本語で表示します。」にします。PC音声を聞いているときは、英語の動画や音声を再生するよう出します。「YouTube字幕だけ」のときは、字幕（CC）をオンにして再生するよう出します。「画面の文字」のときは、選んだ範囲の文字が変わると訳が出ることを出します。音声認識の準備中は、そのことを出し、まだ再生を頼みません。翻訳モデルがないときは、いちばん下の「モデルの準備」を案内します。ミニ表示では、ボタンがチャットの上にあるので「上の「● 聞く」を押すと始まります。」と出し、翻訳モデルがないときは「通常表示」に戻るよう案内します。字幕ウィンドウは、「PCで再生中の英語の音声を、ここにやさしい日本語で表示します。」の1文だけです。
- **「聞く」のバー**：チャットの下に、大きなボタンと一行の説明を置きます。止まっているときのボタンは「● 聞く」、動いているときは「■ 止める」です。`Ctrl+Alt+L` で同じことができ、ボタンのホバーにも出します。
  - **聞く**：選んである入力を始めます。何も選ばなければ「PC音声だけ」です。「自動（字幕を優先）」では、字幕連携から字幕が届いている間は字幕を、届いていないときはPC音声を訳します。YouTubeの窓を最小化したときなどに字幕の表示が止まると、動画が5秒進んだところで拡張機能が字幕のクリアを知らせるので、字幕が届いていないときと同じです。音声認識がまだ準備できていないときは、これまでどおり準備の確認が出ます。
  - **止める**：字幕・PC音声・画面の読み取りのすべてを止めます。保存した訳文は残ります。
  - **一行の説明**：止まっているときは「止まっています」、動いているときは「YouTube字幕を受け取っています」「PC音声を聞いています」「画面の文字を読み取っています」などを出します。「YouTube字幕を受け取っています」は、字幕を訳しているあいだ（最後に届いた字幕から5秒まで）だけ出します。サービスのエラーは、この一行に赤で出します。入力がPC音声を使い、Nemotronが翻訳元の言語を聞き取れないときは、そのことを注意の色で出します（「4. PC再生音声の認識（STT）」を参照）。
  - **翻訳モデルがないとき**：ボタンは押せず、「翻訳モデルの準備が必要です」（読み込み中は「翻訳モデルを準備しています」）と出します。入力が動いているあいだは、モデルが止まっても「止める」を押せます。
  - **自動読み上げ**：「読み上げを使う」がオンのときは、このバーの右に置きます。ほかの画面では、右上の「その他」の左に置きます。声の準備がないときに押すと、設定を開いて「その他の機能」の「訳文の読み上げ」を見せ、「読み上げの準備」の窓を出します（ミニ表示のときは、通常表示に戻ってから開きます）。
- **「その他」メニュー**：次の順に並びます。シンプル翻訳（`Ctrl+1`）、ミニ表示（`Ctrl+Shift+M`）、履歴（`Ctrl+3`）、モデル、設定（`Ctrl+4`）、状態の詳細。チャットの画面では、その下に「入力の切り替え」「書き出し」「表示」（原文をすべて表示・末尾へ自動スクロール・ダークモード・訳文の文字サイズ）も出ます。いちばん下の「その他の機能」には、範囲翻訳（`Ctrl+Alt+T`）、画面の文字を翻訳、画像から翻訳、ファイルを翻訳、字幕ウィンドウ、YouTube字幕の接続があります。モニターが2つ以上あるときは、範囲翻訳の下に「画面選択」が出ます。「入力の切り替え」には、PC音声だけが並びます。「YouTube字幕も訳す」がオンのときは、PC音声だけ・YouTube字幕だけ・自動（字幕を優先）の順に並びます。「画面の文字」は、それが動いている入力か、次の「聞く」で始まる入力のあいだだけ並びます。動いているときに選ぶと、その場で切り替わります。止まっているときに選ぶと、次の「聞く」で始まります。選んだ入力は設定に保存せず、起動すると「PC音声だけ」に戻ります。「画面の文字を翻訳」は、「画面の文字」を選んで、すぐ範囲を選ぶところから始めます。「画像から翻訳」と「ファイルを翻訳」は、シンプル翻訳の画面を開いてから始めます。「画像から翻訳」は、画像ファイルを選ぶと文字を読み取り、その画面で訳します。「ファイルを翻訳」の進み具合と「中止」は、その画面に出ます。「ファイルを翻訳」で訳せるのは、テキスト・Markdown・SRT・WebVTT のファイルで、字幕の時刻は保ちます。範囲翻訳は、画面の好きな範囲をドラッグして選び、`Esc` で中止します。翻訳モデルがないあいだは、ミニ表示・範囲翻訳・画面の文字を翻訳・画像から翻訳・ファイルを翻訳は押せません。モデルの画面でも、ミニ表示は押せません（`Ctrl+Shift+M` を押すと、いちばん下の行に「モデルの画面では、ミニ表示を使えません。」と出ます）。
- **YouTube字幕の接続**：拡張機能の入れ方、接続キーのコピー、字幕の届き方を1つの画面にまとめます。いちばん上に「YouTube字幕も訳す」のスイッチを置きます。その下の札は、アプリを起動してから拡張機能から届いたもので変わります。何も届いていなければ「未接続」、最後に届いたものの接続キーが違えば「接続キーが違います」、再生中の動画の字幕の文字が8秒以内に届いていれば「字幕を受信中」（話の切れ目で字幕が消えても、そのあいだは変わりません）、それ以外で、このアプリの接続キーで届いていれば「接続済み」です。「字幕を受信中」の説明は、「YouTube字幕も訳す」がオフなら、上のスイッチをオンにするよう案内します。オンなら、チャットで聞いているかと、いまの入力が字幕を訳すかで変わります。聞いていないときは、次の「● 聞く」で始まる入力で決めます。その入力が字幕を訳さない（「PC音声だけ」か「画面の文字」）ときは、その名前を出して、字幕は訳さないことと、「入力の切り替え」で選ぶことを案内します。手順の3には、拡張機能を入れる前から開いていたYouTubeのページは、再読み込みすることと、訳すときはスイッチをオンにして入力を選び、「● 聞く」を押すことを書きます。下の注意には、拡張機能のファイルを新しくしたときは、拡張機能の再読み込みボタンを押したあと、開いているYouTubeのページも再読み込みすることを書きます。設定の画面には、同じ札と、この画面を開くボタンがあります。
- **YouTube字幕も訳す**：YouTube字幕はオプションで、既定はオフです。設定の「その他の機能」の「YouTube字幕」と、YouTube字幕の接続の画面のいちばん上にあるスイッチでオンにします。2つは同じ1つの設定で、ほかの設定と同じく設定ファイルに保存します（「設定を保存」と終了のとき）。この項目のない前の版の設定ファイルでは、オフです。オフのあいだは、「入力の切り替え」にPC音声だけが並び（「画面の文字」は使っているあいだだけ）、拡張機能から届いた字幕は訳しません。オフのあいだに文字のある字幕が届くと、いちばん下の行（ミニ表示では下の1行）に「YouTube字幕が届いています。設定の「その他の機能」で「YouTube字幕も訳す」をオンにすると訳せます。」と出します。出すのは、起動してから、またはオフにしてから最初の1回だけです。オンにすると、この案内は消えます（ほかの知らせは残します）。オフにすると字幕を止め、入力が「YouTube字幕だけ」か「自動（字幕を優先）」なら、次の「聞く」は「PC音声だけ」になります。PC音声と画面の文字は止めません。音声認識を準備する前の確認の「YouTube字幕だけを使う場合は不要です。」は、オンのときだけ出します。
- **チャット以外の画面**：上の1行に、左から「← チャットに戻る」（`Ctrl+2`）、その画面の題と説明を置き、右端に「その他」を置きます。モデルの画面も同じです。
- **設定の画面**：いちばん上の「翻訳モデル」に、いま使っているモデルと「モデルを変更」、「翻訳する言語」を置きます。そのあとに、音声認識、文章をつなぐ翻訳、YouTube字幕の接続、「用語集と文脈」「ショートカットと保存先」「詳細（トラブル時）」が続き、最後が「その他の機能」です。幅の広い窓では2列にし、「その他の機能」は右の列の最後に置きます。「その他の機能」は最初は閉じていて、開くと「訳文の読み上げ」「画面・画像の文字認識」「YouTube字幕」があります。「ショートカットと保存先」には、聞く・止める（`Ctrl+Alt+L`）、ミニ表示（`Ctrl+Shift+M`）、シンプル翻訳・チャット・履歴・設定（`Ctrl+1`〜`Ctrl+4`）の3行と、「保存フォルダーを開く」を置きます。ボタンなどの操作部品は、`Tab` で選び、`Enter` か `Space` で押せます。ほかの機能のショートカットは、メニューのその行に出ます。「設定を保存」は、いちばん下に固定します。
- **履歴の画面**：題は「履歴」、説明は「これまでの訳文を探せます。」です。題の下の1行には、「原文・訳文を検索」の欄と「書き出し」だけを置きます。その下に、いまの会話を新しいものから出します。1つの会話は200件まで出し、残りがあれば「さらに表示（残り◯件）」で200件ずつ足します。そのあとの「これまでの会話」には、保存先の `sessions` フォルダーにあるほかの会話ファイルを、新しい会話から順に、会話ごとに閉じた見出し（例：「2026/11/09 19:30 からの会話 · 2件」）で並べます。読み込むのは、あわせて10,000件までです。それより前の会話があるときは「これより前の会話は、保存フォルダーのファイルにあります。」、読めないファイルがあるときは「読めない会話ファイルが◯件あります。」と出します。最後の行が壊れたファイルは並べません。その会話は、次に起動したときに新しいファイルへ写してあるためです。検索は、読み込んだすべての会話を探します。一致する行がない会話は出さず、ある会話は見出しを開いて出します。行の入力元は、チャットと同じ名前（PC音声・画面・YouTube）で出し、範囲翻訳は「範囲翻訳」、シンプル翻訳の「翻訳する」と `Ctrl+Enter` の翻訳は「文章」と出します。
- **シンプル翻訳の画面**：題は「シンプル翻訳」、説明は「左に入れた文を、右に訳します。」です。上の行は、ほかの画面と同じく「← チャットに戻る」、題と説明、「⋯ その他」だけです。その下に翻訳する言語と「翻訳する」（`Ctrl+Enter`）を置きます。言語は、設定の「翻訳する言語」と同じものです。翻訳モデルがないときはその案内を、ファイルを訳しているあいだは「ファイルを翻訳しています」と「中止」を出します。左は原文の欄（「貼り付け」「クリア」）、右は「訳文」の欄（「コピー」「保存」、「読み上げを使う」がオンのときだけ「読み上げ」）です。
  - **ひとりでに訳す**：原文の欄が変わらなくなって1秒たつと、いちばん新しい原文を訳します。翻訳元・翻訳先の言語、「交換」、常体・です・ますを変えたときも、原文が変わったのと同じです。訳すのは、この画面を見ているあいだだけです（ほかの画面で言語を変えたときは、この画面に戻ったときに訳します）。翻訳モデルの準備ができるまでは何も送らず、できたら、いちばん新しい原文を訳します。この画面の翻訳は1つずつです。訳している途中に原文が変わると、終わるのを待ち、そのあいだの古い原文は送らず、いちばん新しい原文だけを送ります。古い原文の訳は届いたときに出し、新しい訳がそのあとに続きます。原文の欄を空にすると訳文も消え、そのあとに届いた訳は出しません。訳文の欄に出ている訳と同じ原文・言語・文体は、どの方法で訳したものでも送り直しません（失敗したものも、原文を変えるまで送り直しません）。ひとりでに訳したものは、履歴に入れず、自動読み上げもしません。
  - **翻訳する・`Ctrl+Enter`**：待たずにすぐ訳し、訳を履歴に入れます（入力元は「文章」）。翻訳モデルの準備ができていて原文があれば、訳している途中でも押せます。そのときは、途中の翻訳が終わるのを待ってから、いちばん新しい原文を訳して1回だけ履歴に入れます。途中の翻訳が、いまの原文そのものの訳なら、送り直さず、その訳を履歴に入れます。待っているあいだに範囲翻訳や画像の文字を読み終えたときは、原文の欄が読み取った文字に置きかわって先に訳され、待っていた「翻訳する」は取りやめます。同じ文字を2回訳して、履歴に2回入れないためです。原文を空にしたあとに届いた訳も、履歴には入ります。
  - **新しい訳を待つあいだ**：自動で訳し直すときと「翻訳する」を押したときは、訳文の欄に、新しい訳の最初の部分が届くまで前の訳を出したままにし、届いたところで替えます。範囲翻訳と画像の読み取りでは、前の訳を残しません（読み取った文とは別の文の訳だからです）。訳し終えるまでは「コピー」「保存」「読み上げ」を押せません。訳せなかったときは、訳文の欄を空にします（訳せなかった原文の訳として、前の訳を出したままにしないためです）。原文の欄を空にしたときは、待たずに訳文を消し、ミニ表示のカードに出る失敗も消します。訳しているあいだに空にしたときも、ミニ表示を開くとチャットが出ます。
- **シンプル翻訳の画面に出る結果**：メニューの範囲翻訳は、結果を出すシンプル翻訳の画面を開いてから始めます。`Ctrl+Alt+T` と画像のドロップは、そのときの画面で始めて、読み取った文字を訳す段でシンプル翻訳の画面に切り替えます（チャットを見ているときも同じ）。読み取った文字は原文の欄に入れて、待たずに訳し、履歴に入れます（入力元は「範囲翻訳」）。読み取れなかったときは、画面を替えず、下の行にそう出します。翻訳モデルがないときの `Ctrl+Alt+T` は、範囲を選ばず、下の行に「モデルの準備ができると、範囲翻訳を使えます。」と出すだけです。ミニ表示のときは、チャットの場所に「訳文」のカードを出すので、画面は替わりません（下の「ミニ表示」を参照）。テキストファイルのドロップは、すぐシンプル翻訳の画面を開いて原文の欄に入れ、打ったときと同じく1秒後に訳します（履歴には入りません）。どれも、ライブ翻訳は止まりません。
- **状態**：チャットの画面では、いちばん下の行の左に、「準備完了」「準備中…」「準備が必要です」のどれかをひとつ出します（ほかの画面には出しません）。翻訳モデルがないと「準備が必要です」になり、横の「モデルの準備」でモデルの画面を開きます。音声認識などは、はじめて使うときに準備するので、まだ準備していなくても「準備完了」のままです。いちばん下の行には、アプリが最後に伝えたこと（「設定を保存しました。」など）も出します。起動したときは、何かが起きるまで何も出しません。サービスのエラーは、チャットの画面では「聞く」の横の一行に、ほかの画面ではいちばん下の行に、赤で出します。「その他」→「状態の詳細」には、翻訳・音声認識・文字認識を、この順に1行ずつ出します（「読み上げを使う」がオンのときは、最後に読み上げも）。行には、使っているモデルや方式の名前も出します。準備完了の行は `●`、ほかの行は `○` に「未準備」か「準備中」を添えます。未準備の行を押すと、準備する画面を開きます。翻訳はモデルの画面、音声認識は設定です。文字認識と読み上げは、設定を開いて「その他の機能」を開き、「画面・画像の文字認識」か「訳文の読み上げ」のところまで進みます。
- **窓の位置と大きさ**：閉じたときの窓の位置と大きさを覚え、次の起動で同じところに開きます。位置と大きさは、起動しているあいだ30秒ごとと、閉じるときに保存します。最小化したまま閉じたときは、画面に出ていたあいだに最後に保存した位置と大きさで開きます。最小化する前の30秒のあいだに窓を動かしていると、動かす前のところに開くことがあります。初めて起動して、一度も保存しないうちに最小化して閉じたときは、既定の大きさ（1180×800）で開きます。覚えている大きさが最小の大きさ（860×620）の半分より小さいときは、既定の大きさ（1180×800）にして、画面のまん中に開きます。以前の版で最小化したまま閉じたPCでは、そうした小さな値が残っています。
- **クレジット**：`translated by PLaMo · Built with PLaMo` は、どの画面でも右下に出します。
- **ミニ表示（`Ctrl+Shift+M` / `Esc`で戻る）**：同じウィンドウを小さくして（520×360、最小400×260）、本体のチャットをそのまま出します。吹き出し、原文、コピー、「↓ 新しいメッセージ」は本体と同じで、表示の設定も本体と共通です。開いたときは、いちばん新しいメッセージから始まります。窓の大きさが変わるあいだ、末尾にいた読み手は末尾のままです（「末尾へ自動スクロール」がオフでも）。本体のチャットは、ミニ表示に入る前の位置のままです。`Esc` は、メニューが開いていればメニューを閉じ、チャットの文字を選んでいれば選択を外し、どちらでもなければ通常表示に戻ります。入力中の文章・履歴・固定声設定は維持されます。
  - **上の行**：左から「通常表示」、「● 聞く」（動いているときは「■ 止める」）、「自動読み上げ」（「読み上げを使う」がオンのとき）を置き、右端に「⋯」を置きます。そのあいだに、「クリア」「全文コピー」「最前面」のうち入るものをこの順に置き、入らないものは「⋯」メニューに出します。メニューへ移るのは全文コピーが先で、次が最前面、最後がクリアです。520×360では、自動読み上げがなければ3つとも、あればクリアと最前面が上の行に入ります。400×260では、なければクリアと最前面が入り、あれば3つともメニューです。入るかどうかは、描くたびに、そのときの拡大率で描くボタンの幅から決めます。「聞く」は本体のボタンと同じ動きで、`Ctrl+Alt+L` も同じです。「クリア」と「全文コピー」は、チャットの上のボタンと同じ動きで、押せるときも同じです。ただし「クリア」は、訳文のカードが出ているあいだは、上の行でもメニューでも押せません（見えていない会話を消さないためです）。「全文コピー」は、カードが出ているあいだもチャットの会話をコピーします。「最前面」は、オンのあいだ選んだ色で塗ります。
  - **下の1行**：本体の「聞く」の横の一行と同じ言葉を、同じ色で出します。保存できていないときは、その前に「保存できていません（…）」を赤で出します。本体のいちばん下の行が字幕の届いている案内（「YouTube字幕も訳す」を参照）を出しているあいだは、同じ案内を「聞く」の横の言葉のうしろに出します。読み上げのエラーは、いちばんうしろに赤で出します。入りきらないときは切り詰め、ホバーで全文を出します。右端はクレジットです。
  - **「⋯」メニュー**：上から、表示（原文をすべて表示・末尾へ自動スクロール・ダークモード・訳文の文字サイズ）、入力の切り替え、上の行に入らなかったクリア・全文コピー・最前面（この順）、その他の機能です。「その他の機能」には、範囲翻訳（`Ctrl+Alt+T`）、画面選択（モニターが2つ以上のとき）、字幕ウィンドウがあります。「最前面」は、ほかの窓より手前に置きます。通常表示に戻ると外れます。
  - **範囲翻訳と画像のドロップの結果**：チャットの場所に「訳文」のカードを出します。読み取っているあいだは「画像から文字を読み取っています…」、訳しているあいだは途中までの訳（まだ何も届いていないあいだは「翻訳中」で、前の訳は出しません）、失敗したときはその理由を出します。カードに出すのは、いちばん新しく起きたことです。訳している途中に別の読み取りが失敗すると、その理由を出し、訳し終えると訳文に替わります。範囲の選択を始めただけでは、カードは変わりません。新しい結果は、先頭の行から出します。訳し終えると「コピー」を押せます（PLaMoのクレジットが付きます）。「← チャットに戻る」でチャットに戻ります。戻ったあとに訳し終えたときと、失敗したときは、もう一度カードを出します。カードを出したまま通常表示に戻ると、シンプル翻訳の画面が開きます。シンプル翻訳の画面に訳文があるときにミニ表示へ切り替えると、その訳文のカードから始まります。
- **独立した字幕ウィンドウ**：通常画面の「その他」→「その他の機能」→「字幕ウィンドウ」、またはミニ表示の「⋯」→「その他の機能」→「字幕ウィンドウ」から別窓で開けます。字幕ウィンドウだけを閉じても翻訳・保存・読み上げは継続します。描くのは本体のチャットと同じ部品ですが、出すのは、いまの入力の訳し終えた部分（新しいほうから100件まで）と、訳している途中の部分だけです。シーク、動画の終わり、別の動画、入力の切り替えでは、最初から出し直します。文字サイズと「原文をすべて表示」は窓の「表示」メニューで変えます。チャットの色は、本体の「表示」の「ダークモード」に従います。

## 7. 保存先とローカル通信

- **保存先**：既定はZIPを展開したフォルダの `data`（アプリ内に実パスを表示）。設定・履歴・モデル・ランタイムを保存します。0.5以前の版で準備した `Local AppData\LocalTools\PlamoTranslate\data` があり、展開したフォルダに `data` がないときは、その場所を使い続けます。展開したフォルダに書き込めないときも `Local AppData` に保存します。開発・検証時は絶対パスの環境変数 `PLAMO_DATA_DIR` で分離可能です。
- **外部送信なし**：モデルの初回取得時を除き、原文・画像・字幕・音声を外部サーバーやクラウドへ送信しません。
- **ローカル待受ポート（`127.0.0.1`）**：
  - `17860`：翻訳（llama.cpp）
  - `17861`：音声認識（Qwen / Whisper）
  - `17862`：YouTube字幕ブリッジ
  - `17863`：読み上げ（speech.cpp）
  - `17864`：英語音声認識（Nemotron）
  - `17865`：PaddleOCR-VL
  - `17866`：Indra OCR

## 8. CLI・ソースからのビルド

通常利用ではGUIからすべて操作できます。コマンドラインから構成確認を行う場合の例：

```powershell
# PC情報と推奨プランの確認のみ（ダウンロードなし）
.\setup.ps1 -Policy realtime -PlanOnly

# セットアップCLIを直接呼ぶ場合
.\jimoto-setup.exe --root C:\LocalModels\Jimoto --policy balanced --probe
```

ソースからビルドする場合は Rust（MSVC）と Windows SDK が必要です。

```powershell
cargo build --release --locked --target x86_64-pc-windows-msvc
```

配布ZIPの作成手順は [docs/DISTRIBUTION.md](DISTRIBUTION.md)、動作確認済みの範囲は [docs/VALIDATION.md](VALIDATION.md) を参照してください。

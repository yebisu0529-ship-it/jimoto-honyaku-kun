# 地元翻訳くん UI/UX 修正 指示書

対象: UI/UX 修正担当（Opus 5.5）
リポジトリ: `yebisu0529-ship-it/jimoto-honyaku-kun`（既定ブランチ `main`）
対象版: 0.5.0 開発版

## 0. この指示書の使い方

- 発注者からの依頼は具体的な仕様ではなく「この方向で」という曖昧なものが多い。**曖昧さは前提**であり、意図を推定して最小の変更で応えるのが仕事。
- 迷ったら「小さい方」「消さない方」「既存の語彙に合わせる方」を選ぶ。
- 判断は消さずに残す。PR 本文かコミットメッセージに「何を・なぜ・捨てた案」を3行。
- ブロッキングな質問は、データ形式・機能の削除・課金や配布に触れる場合だけ。

## 1. プロダクト

Windows 10/11 x64 向けのローカル翻訳アプリ。文章・画面OCR・YouTube字幕・PC音声を翻訳し、読み上げと履歴保存までを PC 内で完結させる。外部送信はしない。

利用者は開発者ではない。UI は日本語。主要導線は4つ。

1. 文章翻訳（貼り付け・画像から翻訳）
2. ライブ翻訳（字幕・PC音声のリアルタイム対訳）
3. 履歴（確定した対訳の一覧・書き出し）
4. 設定（モデル・OCR・音声認識・読み上げ）

範囲翻訳はホットキー、ミニ表示は常駐して使う。初回はモデル準備（セットアップ画面）を通る。

## 2. 技術前提

- Rust 2024 / MSRV 1.88 / eframe 0.33（egui + glow）/ Windows MSVC
- フォントは Noto Sans JP を同梱
- UI の実体:
  - `src/ui.rs` 通常画面（レール・ステータス行・各タブ）
  - `src/theme.rs` 色・余白・文字サイズのトークン
  - `src/mini.rs` ミニ表示
  - `src/subtitle_window.rs` 字幕の別窓
  - `src/setup.rs` 初回セットアップ
  - `src/screen_ocr.rs` OCR 設定、`src/readout.rs` 読み上げ設定
- プレビュー（GUI 不要・CPU 描画）:
  `plamo-translate.exe --render-preview <出力フォルダ>`
  で 27 枚（2560x1369 / 1280x880 / 860x620 + ミニ 520x360・400x260 + 字幕窓）を書き出す。
- 検証:
  `cargo check --all-targets --locked`
  `cargo clippy --all-targets --locked -- -D warnings`
  `cargo test --locked`
  配布ビルド: `cargo build --release --locked --target x86_64-pc-windows-msvc`

## 3. 触ってよい / 触ってはいけない

触ってよい: 余白、字組み、階層、配置、順序、ラベル文言、アイコン、状態表示、フォーカス、キーボード導線、空状態とエラー表示、色（`theme.rs` のトークンの範囲内）。

要相談（勝手に変えない）:

- **コピー・保存・書き出し時のクレジット付与と、その表示**（`translated by PLaMo` / `Built with PLaMo`）。PLaMo Community License 第5条の明示条件であり、法務要件。位置・大きさ・見せ方は変えてよいが、消さない。
- **ステータス行の 翻訳 / OCR / STT / TTS の4状態表示**。表現は変えてよいが、削除しない。
- 翻訳・OCR・STT・TTS・保存・履歴の挙動。設定ファイルと履歴の形式。
- 新しい crate の追加、実行時のネットワーク通信、GPU 前提の描画。
- 初回セットアップの手順と、モデル選択・検証の意味。

## 4. 画面構成

- 左レール 96px: ロゴ、クレジット、タブ4つ、下部に範囲翻訳・音声翻訳
- 中央: 読み物カラム。本文は 20〜28pt で可変
- 下: ステータス行（モデル状態・メッセージ）
- ミニ表示: 520x360（最小 400x260）
- 字幕の別窓: 最前面・クリック透過なし

## 5. 現行デザインルール

`theme.rs` が唯一の出どころ。色は CANVAS / SURFACE / INPUT / BORDER / TEXT / TEXT_SECONDARY / TEXT_MUTED / ACCENT / ERROR / WARNING / SUCCESS。余白は 4/8/12/16/24 の8ptグリッド。角丸は control 8 / card 10。文字は 12 / 14 / 16 / 20。操作部の高さは 32 / 40。

例外として 7.5px（レールのクレジット）と 9px（ミニのクレジット）がある。経緯のある値なので、統合するなら先に代替の置き場所を決める。

## 6. 依頼の翻訳表

| 依頼 | まず見る場所 | やってはいけない |
| --- | --- | --- |
| ダサい / おしゃれに | 余白、字組み、階層、色の数 | 全画面の作り直し |
| 分かりにくい | ラベル、順序、状態表示、初回導線 | 説明文を増やす |
| うるさい / 落ち着かない | 情報の優先度、常時表示の量 | 機能を消す |
| 安っぽい | 角丸・線・影・色の統一 | 装飾の追加 |
| なんか違う | 直前のプレビューとの比較 | 当てずっぽうの再設計 |
| この画面だけ直して | 対象タブと共通部品の境界 | 他タブへの波及を無視 |

## 7. 現状の粗（候補。まず preview で再現確認する）

1. 860x620 でレール下部が窮屈。クレジット 7.5px は小さすぎる可能性。
2. ステータス行が1行に詰まる（4状態＋モデル名＋状態＋メッセージ）。ドットの意味がホバー頼み。
3. ミニ 400x260 で本文が行の途中で切れる。
4. ライブの操作群が左右2箇所に分かれ、優先度が読みにくい。
5. 履歴行のコピー／読み上げが行ごとに反復していて視線が散る。
6. 設定が縦に長く、初回セットアップと情報が重複している。
7. 8.5 / 7.5 / 9px など、トークン外の文字サイズが点在。
8. フォーカスリングとキーボード操作の見え方が未確認。

## 8. 進め方

- **1 PR = 1テーマ**（例:「ステータス行の情報設計」）。複数テーマを混ぜない。
- 各 PR に before / after のプレビュー（1280x880 と 860x620 の2枚で十分）。
- 文言を変えたら README の該当箇所も直す。
- 破壊的変更（設定項目の追加・削除、保存形式の変更）は事前に確認。

## 9. 検証

- `cargo check --all-targets --locked` / `cargo clippy --all-targets --locked -- -D warnings` / `cargo test --locked`
- `--render-preview` が 27 枚をエラーなしで出力
- 860x620 と 400x260 で、クリップ・重なり・はみ出しがない
- キーボードのみで主要導線を辿れる。フォーカスが見える
- 文字サイズと色は `theme.rs` 経由。直値を増やす場合は理由を残す
- クレジットと4状態が消えていない

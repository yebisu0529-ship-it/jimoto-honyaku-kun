# 0.4.0と0.3.0の検証範囲

## 0.4.0の追加確認

2026-11-05、同じWindows x64・RTX 4090のPCで、公式Nemotron Speech Streaming English 0.6BのQ8_0 GGUF、699,872,960バイトを取得し、固定したSHA-256との一致を確認しました。NVIDIA NeMo-Speech.cpp 0.3.0のVulkan版を取得し、選択モデルの識別、所有プロセスの接続先、実際の英語認識を確認しました。

FRB公式会見の同じ10秒音声でREST認識と160ms単位のWebSocket送信を試し、確定結果が複数の時刻付き区間で返ることを確認しました。モデルを常駐させ、CPU・Vulkanの実行方式を起動引数と応答の両方で確認した結果です。一括認識は各条件3回の平均、最初の英文表示は実時間で音声を送った際の観測値です。

| Nemotron実行方式 | モデルの音声処理単位 | 10秒音声の認識平均 | 最初の暫定英文 |
| --- | --- | --- | --- |
| Vulkan | 560ms | 363ms | 1.636秒 |
| Vulkan | 160ms | 873ms | 1.316秒 |
| CPU | 560ms | 522ms | 1.665秒 |
| CPU | 160ms | 481ms | 1.349秒 |

同じ入力のQwen CUDAは3回で1.262秒・1.111秒・1.078秒、平均約1.150秒でした。モデルの読み込み・録音待ち・翻訳処理を含む全体時間ではありません。Nemotronは4条件とも確定字幕、状態リセット、所有プロセス終了、ポート解放まで成功しました。正解の全文との単語誤り率は測定しておらず、精度の優位は未評価です。

読み上げは、同じ日本語・同じseedを使ってメモリー内で生成し、速度1.0倍で5.32秒、1.4倍で3.80秒、1.8倍で2.96秒の音声になりました。この検査では再生や音声ファイルの保存を行っていません。自動加減速・停止世代・手動読み上げの分離も自動検査に含めています。

追加後のRust自動検査90件が成功し、全ターゲットのClippyも警告ゼロでした。範囲OCRの実マウス操作、追加したNemotronを使うGUI、ライブ字幕からの自動加速読み上げは、実操作による確認が残っています。

## 0.3.0を起点とした導入・処理の確認

2026-11-05、Windows x64・RTX 4090のPCで確認しました。公開済み0.2.1のZIPを起点に、0.3.0で修正した導入・処理経路を検証した結果です。別のクリーンなWindows OSでの確認ではありません。

## 初回導入と翻訳モデル

公開ZIPを匿名で取得し、公開SHA-256との一致を確認して、新しい日本語名のフォルダーへ展開しました。空の保存領域をPLAMO_DATA_DIRで指定し、初回起動、RAM・GPU・ディスクの検出、8Bの推奨表示を確認しました。8Bの取得を中止しても未完了ファイルが保持されることを確認しています。8Bの大容量ダウンロードは途中保存のままです。

処理の確認には手動で公式0.8B Q4_K_M・CUDAを選び、重み573,116,288バイトの取得とSHA-256照合、固定版ランタイム・テンプレートの取得完了を確認しました。検証用の1文は約207msで翻訳できました。この小型モデルでの結果を、8Bの取得完了や全14モデルの性能確認として扱っていません。

範囲選択の開始時にアプリが隠れたままになる不具合は、所有するWin32ウィンドウを一時的に隠し、取得後にRAIIで復帰する処理へ変更して修正しました。取得エラーやRust panic時にも復帰する構成です。修正後の実マウスドラッグによる範囲選択については、まだ検証していません。

## 任意の音声認識

空の保存領域から、アプリ専用uv、管理Python 3.13.14、分離したvenv、PyTorch CUDA12.8、固定版Qwen3-ASRモデルを実際に取得しました。日本語パスのUTF-8設定ファイルをcp932で読み込んで失敗する不具合を修正し、取得済みデータを保持して再開しました。再開した導入は2352.80秒で完了しました。

実ファイルのSHA-256が公式情報と一致し、Python・依存・HFキャッシュが新しいアプリ専用領域内にあることを確認しました。オフラインでモデルをロードし、7.663秒の既知英語WAVを約4.880秒で文字起こしして、期待文との一致を確認しました。一時的な試験サーバーは終了し、試験ポートが閉じたことも確認しました。

音声認識環境の初回空き容量目安は、Qwen CUDAが14GiB、Qwen CPUが8GiB、Whisper CPUが4GiBです。翻訳モデルの準備とは別に計算します。再開時はアプリ専用キャッシュの検証結果を使って必要な残容量を減らします。日本語パスの設定ファイル読み込みと、システムのPythonパッケージを混在させないことの回帰検査も成功しました。

## 並行処理と再生音声の取得

CLIによる本番処理の追試では、Windows OCRが約16ms、その結果のPLaMo 0.8B/CUDA翻訳が約64msでした。同じASR・翻訳サーバーを使う並行処理でも、既知英語WAV 7.663秒の認識が約2.253秒、その翻訳が約57msで成功しました。

さらに同じWAVをWindowsの既定出力へCLIで再生し、本番WASAPIで8秒間取得して、音声認識・翻訳まで成功しました。この経路の認識は約1.204秒、翻訳は約51ms、取得スレッドの停止・joinは約13msでした。

## 日本語の読み上げ

speech.cpp 0.10.1の公式Windowsランタイム約29.5MBと、Irodori-TTS v4.1 Small-MFのF16モデル約1.92GBを取得・照合しました。native info、実際の日本語音声生成・再生・停止・再開、再生後の自声抑止解除を確認しました。ASRとPLaMoの両モデルを常駐させた追試でも同じ動作が成功しました。TTS専用のPython環境は使用していません。

読み上げ開始までは、初回のシェーダー準備を含む実行で約33.7秒でした。シェーダーキャッシュがある状態の起動では約2.53秒、停止後の再起動では約1.94秒でした。本書の所要時間はいずれもこのPCと検証文での観測値であり、一般的な速度保証ではありません。公式WindowsランタイムはVulkan版のため、CPU実行を選んでもシステムのVulkanローダーが必要です。

試験後は、所有する翻訳・音声認識・読み上げプロセスがすべて終了し、使用ポートが閉じたことを確認しました。

## 自動検査と未検証の範囲

アプリ本体と初期設定ツールはVisual C++ランタイムを静的に組み込み、完成EXEのインポート一覧にVCRUNTIME/MSVCP140 DLLへの依存がないことを確認しました。外部のllama.cpp実行環境にはMicrosoft公式のx64再頒布可能パッケージが別途必要です。

Rustの最終自動検査70件（ライブラリ52件・GUI18件）が成功し、全ターゲットのClippyは警告ゼロ、全バイナリのreleaseビルドも成功しました。ASRのHTTP・WAV・言語・生成上限などのPython検査、Windows PowerShell 5.1の診断・計画モードも確認しました。取得処理では途中再開、Range応答、ハッシュ不一致、中止、不正なZIPパス、既存のモデル選択の保持を検査しています。画面・状態表示の日本語の校正にはGemini4Argon CLIを使用しました。

後続のデモ準備では、専用ブラウザーのFRB公式会見アーカイブで拡張機能からの字幕受信・日本語の訳文表示を確認しました。Qwenで会見音声から英語と日本語のタイムラインを表示する操作と、彩りTTSの手動読み上げも収録しました。全14モデルの速度比較、AMD/Intel GPUでの推論、別のクリーンなWindows OS、修正後の実マウスドラッグによる範囲選択は未検証です。

推奨モデルは現在の容量と応答速度を考えた初期値です。すべてのPCでの最速・最高品質や、音声翻訳が常にリアルタイムに追いつくことを示すものではありません。
